# Контракт XQueryInspector.dll

## Публичный API

`XQueryInspector.Inspector` предоставляет `Describe(value)` для получения типа объекта и
`Inspect(provider, xquery)` для трансляции XQuery. Текущая версия DLL — `1.3.1`, мажорная версия
JSON-контракта — `1`.

## Формат результата

`Inspect()` возвращает JSON со следующими полями:

- `success` — SQL удалось извлечь, а коллекцию освободить;
- `contractVersion`, `inspectorVersion` — версии JSON-контракта и DLL;
- `providerType`, `collectionType`, `innerCollectionType`, `queryType` — диагностические типы;
- `providerAssemblyVersion`, `collectionAssemblyVersion`, `innerCollectionAssemblyVersion`,
  `queryAssemblyVersion` — версии сборок среды выполнения;
- `queryRuntimeType`, `reflectionPath` — тип Query и цепочка доступа к команде;
- `xQuery`, `effectiveXQuery`, `sql`, `countSql` — исходный и эффективный XQuery, SQL и Count SQL;
- `sqlOffset`, `pageSize` — включена ли постраничная обработка UniBridge и фактический размер страницы;
- `parameters` — имя, тип и значение каждого параметра;
- `failureStage`, `errorType`, `error`, `cleanupError` — этап и данные ошибок;
- `timingsMs` — длительности этапов и всего вызова.

`success=true` не означает, что SQL синтаксически корректен. Шаблон показывает ответ старой DLL без
версии с предупреждением. Неизвестная версия показывается только как исходный JSON. Безопасный порядок
обновления: сначала шаблон, затем DLL.

При `sqlOffset=true` SQL возвращается до чтения коллекции. Во время чтения UniBridge может добавить
сортировку и постраничную выборку; если при вызове передан нулевой размер страницы, коллекция заменяет
его на `400`. Поэтому реально выполняемая команда может отличаться от поля `sql`.

## Типы и значения параметров

Тип берётся из `NpgsqlDbType` для PostgreSQL, `SqlDbType` для MSSQL, затем из общего `DbType`.
Составной `NpgsqlDbType.Array | NpgsqlDbType.Varchar` отображается как `varchar[]`. Для неизвестного провайдера
сохраняется имя типа значения в среде выполнения.

`Int64` и `UInt64` за пределами безопасного диапазона JavaScript `±9007199254740991`, а также `Decimal`,
сериализуются строками, чтобы не допустить округление при `JSON.parse()`.

## Подготовка иерархии для старых версий

В окружении с `UNI_CAP_BASIC` двухаргументный `Inspect()` воспроизводит строковую подготовку `tools.xquery()`
сборки 434. `IsHierChild()` и `IsHierChildOrSelf()` удаляются из условия, а ID и режим `-` или `+`
переносятся в `/Hier()`. Это воспроизведение штатного алгоритма, а не общий парсер иерархических
выражений.

Перегрузка `Inspect(provider, xquery, useBasicHierarchyPreprocessing)` позволяет явно указать режим.
Двухаргументный вызов предполагает `UNI_CAP_BASIC`. Если в запросе нет `/Hier()`, ID некуда перенести
и SQL теряет иерархическое ограничение, даже если `Inspect()` завершился успешно.

## Ограничения нормализации

На один вызов `Inspect()` действуют следующие пределы:

- 10000 параметров команды;
- 10000 элементов в каждом `IEnumerable`;
- 16 уровней вложенности `IEnumerable`;
- 100000 нормализованных узлов суммарно;
- 1000000 символов Unicode в строковых значениях суммарно;
- 1048576 байт в одном `byte[]`.

При превышении предела инспектор возвращает `success=false` и `failureStage="read-parameters"` без частичного
списка параметров. Циклические структуры также отклоняются. Коллекция UniBridge и итераторы
`IDisposable` при этом освобождаются.

## Внутреннее устройство

Подтверждённая цепочка доступа к команде:

```text
UniBridge → DocumentCollection → UniBridge_DocumentCollection → Query
```

Неизвестный путь доступа сначала добавляется в DLL и smoke-тест с имитацией среды. После этого
требуется повторный стендовый прогон.

Имя сборки и пространство имён `XQueryInspector` не начинаются с `Websoft.` или `Datex.`. Загрузчик
сборки 434 считает имена с этими префиксами системными и требует для них токен открытого ключа
WebSoft.
