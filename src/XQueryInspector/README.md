# Контракт XQueryInspector.dll

## Публичный API

`XQueryInspector.Inspector` предоставляет `Describe(value)` для получения типа объекта,
`Inspect(provider, xquery)` для трансляции XQuery и `Execute(provider, xquery)` для полного
выполнения без возврата строк. Текущая версия DLL — `1.5.1`, мажорная версия JSON-контракта — `1`.

## Формат результата

`Inspect()` и `Execute()` возвращают JSON со следующими полями:

- `success` — выбранная операция и освобождение коллекции завершились без ошибки;
- `contractVersion`, `inspectorVersion` — версии JSON-контракта и DLL;
- `operation` — `inspect` или `execute`;
- `providerType`, `collectionType`, `innerCollectionType`, `queryType` — диагностические типы;
- `providerAssemblyVersion`, `collectionAssemblyVersion`, `innerCollectionAssemblyVersion`,
  `queryAssemblyVersion` — версии сборок среды выполнения;
- `queryRuntimeType`, `reflectionPath` — тип Query и цепочка доступа к команде;
- `xQuery`, `effectiveXQuery`, `sql`, `countSql` — исходный и эффективный XQuery, SQL и Count SQL;
- `sqlOffset`, `pageSize` — включена ли постраничная обработка UniBridge и фактический размер страницы;
- `parameters` — имя, тип и значение каждого параметра;
- `executionAttempted`, `executionSuccess`, `rowsRead` — состояние полного перечисления;
- `timeoutSeconds`, `timedOut` — заданный общий срок выполнения и признак его превышения;
- `executedSql`, `executedParameters` — команда, повторно прочитанная из `Query.command`
  после выполнения;
- `executedCommandCaptureError` — отдельная ошибка повторного чтения команды;
- `failureStage`, `errorType`, `error`, `cleanupError` — этап и данные ошибок;
- `timingsMs` — длительности этапов и всего вызова.

Для `Inspect()` значение `success=true` не означает, что SQL синтаксически корректен. Для
`Execute()` оно означает, что коллекция полностью перечислена и освобождена. Шаблон показывает
ответ старой DLL без версии с предупреждением. Неизвестная версия остаётся доступна как исходный
JSON без интерпретации. Безопасный порядок обновления: сначала шаблон, затем DLL.

## SQL до и после выполнения

Поле `sql` содержит `Query.command.CommandText`, прочитанный до перечисления коллекции. При
`sqlOffset=true` UniBridge может добавить сортировку и постраничную выборку; если при вызове
передан нулевой размер страницы, коллекция заменяет его на `400`. Поэтому `sql` следует считать
предварительной командой транслятора.

`Execute()` после полного перечисления повторно читает команду и параметры в `executedSql` и
`executedParameters`. Для получения этих полей XQuery действительно выполняется. Результирующие
строки при этом подсчитываются в `rowsRead`, но не сериализуются.

`executedSql` остаётся наблюдаемым снимком объекта UniBridge, а не гарантированной трассировкой
драйвера или СУБД. При постраничном выполнении UniBridge может отправить несколько команд; снимок
после перечисления может отражать только последнее доступное состояние `Query.command`.

Поля `parameters` и `executedParameters` являются частью команды наравне с текстом SQL. Строка,
полученная ручной подстановкой значений параметров, предназначена только для чтения и не является
доказательством фактически отправленного запроса.

`countSql` формируется вместе с основным запросом, но `Inspect()` и `Execute()` отдельно его
не выполняют.

Для коллекций UniBridge выполнение использует штатный курсор `GetFirst()`/`GetNext()`; стандартный
`IEnumerable` поддерживается как резервный путь для совместимых реализаций коллекции.

Метод `ExecuteWithTimeout(provider, xquery, executionTimeoutSeconds)` принимает целое значение от 1 до
3600 секунд. Он устанавливает оставшееся время в `Query.command.CommandTimeout` и параллельно
контролирует общий срок перечисления. При превышении срока команда получает `Cancel()`, цикл больше
не начинает следующую строку или страницу, а коллекция штатно освобождается через `Terminate()`.
Таймер начинается до `provider.XQuery()`, однако синхронную трансляцию UniBridge прервать нельзя:
если срок истёк на этом этапе, основной SQL не запускается после возврата коллекции.

## Типы и значения параметров

Тип берётся из `NpgsqlDbType` для PostgreSQL, `SqlDbType` для MSSQL, затем из общего `DbType`.
Составной `NpgsqlDbType.Array | NpgsqlDbType.Varchar` отображается как `varchar[]`. Для неизвестного провайдера
сохраняется имя типа значения в среде выполнения.

`Int64` и `UInt64` за пределами безопасного диапазона JavaScript `±9007199254740991`, а также `Decimal`,
сериализуются строками, чтобы не допустить округление при `JSON.parse()`.

## Подготовка иерархии для старых версий

В окружении с `UNI_CAP_BASIC` двухаргументный `Inspect()` воспроизводит строковую подготовку `tools.xquery()`
сборки 434. `IsHierChild()` и `IsHierChildOrSelf()` удаляются из условия, а ID и режим `-` или `+`
переносятся в `/Hier()`. Это воспроизведение штатного алгоритма, а не общий парсер иерархических
выражений.

Перегрузка `Inspect(provider, xquery, useBasicHierarchyPreprocessing)` позволяет явно указать режим.
Двухаргументный вызов предполагает `UNI_CAP_BASIC`. Если в запросе нет `/Hier()`, ID некуда перенести
и SQL теряет иерархическое ограничение, даже если `Inspect()` завершился успешно.

## Ограничения нормализации

На один вызов `Inspect()` или `Execute()` действуют следующие пределы:

- 10000 параметров команды;
- 10000 элементов в каждом `IEnumerable`;
- 16 уровней вложенности `IEnumerable`;
- 100000 нормализованных узлов суммарно;
- 1000000 символов Unicode в строковых значениях суммарно;
- 1048576 байт в одном `byte[]`.

При превышении предела инспектор возвращает `success=false` и `failureStage="read-parameters"` без частичного
списка параметров. Циклические структуры также отклоняются. Коллекция UniBridge и итераторы
`IDisposable` при этом освобождаются.

## Внутреннее устройство

Подтверждённая цепочка доступа к команде:

```text
UniBridge → DocumentCollection → UniBridge_DocumentCollection → Query
```

Неизвестный путь доступа сначала добавляется в DLL и smoke-тест с имитацией среды. После этого
требуется повторный стендовый прогон.

Имя сборки и пространство имён `XQueryInspector` не начинаются с `Websoft.` или `Datex.`. Загрузчик
сборки 434 считает имена с этими префиксами системными и требует для них токен открытого ключа
WebSoft.
