# websoft-xquery-inspector

Диагностический инструмент для просмотра SQL, который активный провайдер
UniBridge в WebSoft HCM формирует из XQuery.

Инструмент работает в двух режимах:

| Режим | Обращение к БД за данными | Что показывает |
| --- | --- | --- |
| Инспекция | Нет | Предварительные SQL, Count SQL и параметры после трансляции XQuery |
| Выполнение | Да | Статус полного выполнения и снимок SQL-команды, наблюдаемый после него |

Результирующие строки не показываются и не возвращаются клиенту. В режиме выполнения
коллекция полностью перечисляется, чтобы ошибки чтения не были приняты за успешное завершение.

## Предварительный и наблюдаемый SQL

Инспекция не может гарантированно показать окончательный запрос к СУБД. Она получает
`Query.command` до чтения коллекции, а UniBridge может позднее изменить команду — например,
добавить сортировку и пагинацию при `SqlOffset`. Параметры также передаются драйверу отдельно,
поэтому SQL с подставленными значениями не является фактически отправленной командой.

Чтобы получить более близкое к выполнению представление, нужно запустить режим «Выполнение».
Он реально обращается к БД, полностью читает коллекцию и затем повторно получает `Query.command`
и параметры. Эти данные возвращаются как `executedSql` и `executedParameters`.

`executedSql` — наблюдаемый снимок UniBridge, а не трассировка драйвера или СУБД. При постраничном
чтении могло быть выполнено несколько команд, а снимок после завершения не обязан описывать их все.
Для строгого подтверждения фактических команд нужны журналирование драйвера, журнал запросов
PostgreSQL либо MSSQL Profiler/Extended Events.

`Count SQL` формируется и показывается в обоих режимах, но инспектор отдельно его не выполняет.

## Быстрый старт

Для сборки нужны Node.js `22.23.1`, .NET SDK `10.0.1xx`, targeting packs
`net6.0` и `net9.0`. Полная проверка также требует среды выполнения .NET `6.0.36`
и `9.0.20`.

```bash
node tools/verify.js
```

Основные артефакты:

| Артефакт | Назначение |
| --- | --- |
| `src/XQueryInspector/bin/Release/net6.0/XQueryInspector.dll` | Серверная библиотека |
| `websoft/websoft-xquery-inspector.html` | Браузерный интерфейс и серверный обработчик |

## Установка

### DLL

1. Скопируйте `XQueryInspector.dll` в `dotnetcore/tempdll/` целевого экземпляра
   WebSoft HCM.
2. Проверьте наличие `dotnetcore/tempdll` в `DOTNETLIBS-PATH` файла `xHttp.ini`.
3. При замене уже загруженной DLL перезапустите этот экземпляр WebSoft HCM.

### Браузерный интерфейс

1. Создайте настраиваемый шаблон с кодом `websoft-xquery-inspector`.
2. Скопируйте в него `websoft/websoft-xquery-inspector.html` целиком.
3. Сохраните шаблон в UTF-8 с BOM.
4. Опубликуйте его через маршрут портала и ограничьте доступ администраторами.
5. Открывайте инспектор напрямую по адресу
   `/custom_web_template.html?object_code=websoft-xquery-inspector`. Страница документа
   `/_wt/doc_type/custom_web_template.html` ограничивает ширину шаблона и не предназначена
   для работы с его интерфейсом.

Подробности сборки и устройства шаблона приведены в
[документации WebSoft](websoft/README.md).

## Прямой вызов

```js
var assembly = tools.dotnet_host.Object.GetAssembly(
    'XQueryInspector.dll'
)
var inspector = assembly.CreateClassObject(
    'XQueryInspector.Inspector'
)

var result = inspector.Inspect(
    tools.spxml_unibridge.Object.provider,
    "for $elem in collaborators " +
    "where $elem/id = 1111111 " +
    "return $elem/Fields('id', 'fullname')"
)

alert(result)
```

Для выполнения XQuery без возврата результирующих строк используйте `Execute()`:

```js
var result = inspector.Execute(
    tools.spxml_unibridge.Object.provider,
    "for $elem in collaborators return $elem/id"
)
```

Для выполнения с общим тайм-аутом в секундах используйте `ExecuteWithTimeout()`:

```js
var result = inspector.ExecuteWithTimeout(
    tools.spxml_unibridge.Object.provider,
    "for $elem in collaborators return $elem/id",
    30
)
```

[Формат JSON, лимиты и особенности старых сборок](src/XQueryInspector/README.md)
описаны отдельно.

## Безопасность и ограничения

- Для работы нужны внешнее SQL-хранилище и активный
  `tools.spxml_unibridge.Object.provider`.
- Новые сборки UniBridge требуют отдельной проверки.
- При `LuceneFTIndex=True` предварительный SQL возвращается до поздней подстановки результатов Lucene.
- Успешная трансляция не подтверждает синтаксическую корректность SQL.
- Режим выполнения действительно обращается к БД и полностью читает коллекцию. Большой или
  неоптимальный запрос может выполняться долго и создавать нагрузку на сервер и СУБД.
- В интерфейсе выполнение по умолчанию ограничено 30 секундами. Тайм-аут отменяет активную
  SQL-команду и прекращает дальнейшее перечисление, но не может прервать синхронную трансляцию
  внутри `provider.XQuery()`.
- Наличие `executedSql` не доказывает, что снимок содержит все команды постраничного выполнения.
- XQuery, SQL, параметры и тексты ошибок могут содержать чувствительные данные. Доступ к
  интерфейсу следует ограничить администраторами.
