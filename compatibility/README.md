# Матрица совместимости WebSoft HCM

Машинным источником статусов служит [`matrix.json`](matrix.json). Статус
`Проверено` означает успешный стендовый прогон с фактическим UniBridge-
провайдером. Статическое совпадение DLL или декомпилированного кода не повышает
статус. `Не проверено` не означает несовместимость.

| `2023.2.906` | `net6.0` | Проверено 13.09.2026 | Проверено 13.09.2026 |
| `2025.1.1132` | `net6.0` | Проверено 13.09.2026 | Проверено 13.09.2026 |
| `2025.1.1333` | `net6.0` | Проверено 13.09.2026 | Проверено 13.09.2026 |
| `2025.2.1525` | `net9.0` | Проверено 14.09.2026 | Проверено 14.09.2026 |

Сборка 1515 отменена вендором и заменена сборкой 1525. На сборке 1525
подтверждена загрузка `XQueryInspector.dll`, собранной для `net6.0`, в
`net9.0` host с Microsoft.NETCore.App `9.0.19`; multi-targeting не требуется.

Для MSSQL 434 подтверждён полный ручной протокол с DLL `1.2.1`, включая
`Describe(provider)`, обычную инспекцию, SQL и Count SQL, параметры,
reflection, timings, cleanup, паритет `IsHierChild*() + Hier()`, границу
XQuery и ошибочный запрос. Точная patch-версия встроенного .NET runtime в
прежних стендовых результатах не сохранялась, но это не меняет статус
покрытия.

Для PostgreSQL 434 подтверждён полный протокол с DLL `1.3.0`: агент
выполнил пять обязательных сценариев без `FAIL`; отдельно проверены массив
`varchar[]`, успешная трансляция XQuery длиной 200000 кодов и отклонение
неполного XQuery на этапе `invoke-xquery`. Ошибочный вызов не создал
коллекцию, поэтому cleanup для него не требовался; в сценариях, где коллекция
создавалась, `cleanupError` отсутствовал.

Для сборки 906 владелец подтвердил полный протокол на MSSQL и PostgreSQL.
Точные версии встроенного .NET runtime и инспектора для нового MSSQL-прогона
не переданы и оставлены пустыми в обезличенном результате.

Для сборок 1132 и 1333 владелец подтвердил полный протокол на обеих СУБД.
Точные версии runtime и инспектора, а также названия фактических PostgreSQL-
типов не переданы; результаты сохраняют это ограничение, не подставляя
предполагаемые значения из сборки 906.

Для сборки 1525 полный протокол подтверждён на MSSQL и PostgreSQL с UniBridge
`2.26.8.12` и DLL `1.3.0`. На обеих СУБД прошли пять автоматизированных
сценариев, успешная граница 200000 кодов и отклонение неполного XQuery на
этапе `invoke-xquery`; `cleanupError` отсутствовал. На MSSQL дополнительно
подтверждён паритет иерархических запросов со штатным `tools.xquery()`. На
PostgreSQL `16.3` проверены скалярный `varchar` и массив `varchar[]`; для
массива provider сформировал оператор пересечения `&&` с одним параметром.

13.09.2026 обязательный автоматизированный набор агента с DLL `1.3.0` прошёл
без `FAIL` на MSSQL и PostgreSQL сборок 434, 906, 1132 и 1333. Полный статус
присваивается только вместе с результатами ручных пунктов, перечисленных ниже.
14.09.2026 тот же набор и ручные пункты полного протокола прошли на MSSQL и
PostgreSQL сборки 1525.

## Протокол стендового прогона

Для каждого сочетания используется свежая поставочная DLL и тестовые ID без
персональных данных. Полный JSON и журналы в Git не добавляются.

Основные проверки пунктов 2–7 автоматизирует поставочный серверный агент
[`websoft/xquery-inspector-compatibility-agent.js`](../websoft/xquery-inspector-compatibility-agent.js).
Его запускают вручную внутри проверяемого WebSoft HCM; успешным считается
только завершённый блок журнала с `XQI|SUMMARY|...|failed=0|...`. Статус матрицы
обновляется после просмотра журнала человеком, а не самим агентом. PostgreSQL-
массив, успешная граница 200000 кодов, ошибка парсера UniBridge и остальные
сведения пункта 1 остаются ручной частью полного протокола.

Дополнительный агент
[`websoft/xquery-inspector-compatibility-agent-2.js`](../websoft/xquery-inspector-compatibility-agent-2.js)
автоматизирует ручную границу 200000 кодов и ошибку парсера, а также сохраняет
данные для сравнения иерархических запросов со штатным `tools.xquery()`. Он
предназначен только для изолированного стенда: `tools.xquery()` выполняет
запросы, а отдельный журнал `xquery_inspector_manual` содержит полный JSON с
XQuery и SQL. Этот журнал нельзя добавлять в Git.

1. Записать дату, версии WebSoft, UniBridge, SQL-провайдера, фактического .NET
   runtime и `XQueryInspector.dll`.
2. Загрузить DLL штатным
   `tools.dotnet_host.Object.GetAssembly("XQueryInspector.dll")`, создать
   `XQueryInspector.Inspector` и сохранить обезличенный результат
   `Describe(tools.spxml_unibridge.Object.provider)`.
3. Вызвать `Inspect()` для обычного запроса с тестовым ID. Коллекцию не
   перечислять, сформированные SQL и Count SQL не выполнять.
4. Проверить `success`, SQL, Count SQL, имена, типы и обезличенные значения
   параметров, `reflectionPath`, четыре assembly version, все начатые timings и
   отсутствие `cleanupError`.
5. На MSSQL проверить `IsHierChild()` и `IsHierChildOrSelf()` совместно с
   `Hier()`. Сопоставить `effectiveXQuery`, SQL и параметры со штатным
   `tools.xquery()` в серверном debug-режиме.
6. На PostgreSQL проверить отдельные запросы со скалярной строкой и массивом.
   Записать фактический тип; ожидаемая для подтверждённого 906 форма массива —
   `varchar[]`.
7. Проверить 200000 и 200001 Unicode-кодов и синтаксически ошибочный XQuery.
   Для запроса, который создал коллекцию до ошибки, убедиться в успешном
   cleanup. Граница длины до вызова провайдера коллекцию не создаёт.
8. Обновить публичные `matrix.json` и README. Исходные результаты, версии
   локальных файлов и журналы хранить только в приватном хранилище. При
   несовместимости публиковать лишь статус и обезличенное ограничение без
   полного запроса, SQL, подключений и журналов.

Если обнаружен новый `reflectionPath`, сначала добавляются именованный resolver
и fake smoke-сценарий. Только повторный стендовый прогон позволяет отметить
сочетание проверенным.

## Локальная проверка реестра

```bash
node tests/compatibility-matrix-smoke.js
```

Проверка требует ровно десять сочетаний, сверяет публичную таблицу README с
матрицей и наличие именованного C# smoke-сценария для каждой
зарегистрированной runtime-структуры. Она не читает приватные evidence-файлы и
не заменяет стендовый прогон.
