# Шаблон WebSoft

## Сборка и установка шаблона

`websoft/websoft-xquery-inspector.html` — сгенерированный поставочный файл. Его исходные
части находятся в `websoft/src/`; готовый файл не редактируют вручную.

```bash
node tools/build-template.js
node tools/build-template.js --check
```

Первая команда пересобирает шаблон, вторая только проверяет его актуальность. Для поставочного
файла зафиксированы UTF-8 BOM и окончания строк CRLF.

Для установки:

1. Создайте настраиваемый шаблон с кодом `websoft-xquery-inspector`.
2. Скопируйте в него `websoft/websoft-xquery-inspector.html` целиком, включая вставки `<% %>`.
3. Сохраните шаблон в UTF-8 с BOM.
4. На время разработки отключите `use_session_cache`.
5. Опубликуйте шаблон через маршрут портала и ограничьте доступ администраторами.

Это содержимое настраиваемого шаблона, а не файл для каталога xHttp.
Инспектор следует открывать напрямую по адресу
`/custom_web_template.html?object_code=websoft-xquery-inspector`. Страница документа
`/_wt/doc_type/custom_web_template.html` встраивает шаблон в ограниченную по ширине область
и предназначена для администрирования, а не для работы с интерфейсом инспектора.

## HTTP-интерфейс

GET возвращает HTML-фрагмент. POST-запрос через AJAX отправляет `action=inspect` либо
`action=execute`, `xquery` и для выполнения `timeout_seconds` на:

```text
/custom_web_template.html?object_code=websoft-xquery-inspector
```

Обработчик возвращает JSON без HTML-обёртки портала и сохраняет штатную проверку доступа к
шаблону. Длина XQuery ограничена 200000 символов: интерфейс проверяет строку до отправки,
серверный обработчик отклоняет запрос до загрузки DLL, а методы DLL повторяют ограничение.
Тайм-аут выполнения по умолчанию равен 30 секундам, допустимый диапазон — 1–3600 секунд.
API сохраняет HTTP 200 и передаёт прикладные ошибки через `success=false`, `failureStage`,
`errorType` и `error`: некоторые версии xHttp отправляют заголовки во время долгой операции,
после чего вложенный настраиваемый шаблон уже не может безопасно изменить HTTP-статус.

## Интерфейс и данные

Интерфейс содержит редактор, отдельные кнопки инспекции и выполнения, блоки SQL,
Count SQL и эффективного XQuery, таблицу параметров, общую диагностику и раздельные
JSON-ответы.

Инспекция получает предварительный `Query.command` без чтения коллекции. Выполнение
полностью перечисляет коллекцию, отбрасывает строки и возвращает только статус, ошибку
и диагностические данные. После выполнения DLL повторно читает `Query.command` и параметры.
Это наблюдаемый снимок UniBridge, а не гарантированная трассировка СУБД. При `SqlOffset`
могут выполняться разные команды для отдельных страниц результата.

Результаты инспекции и выполнения сохраняются в отдельных вкладках. Общий раздел
«Технические данные» накапливает диагностику обеих операций и хранит их исходные
JSON-ответы раздельно. Изменение текста редактора помечает данные как относящиеся к
предыдущему запросу; запуск изменённого XQuery начинает новую сессию и очищает
несовместимый результат другой операции.

При включённом `SqlOffset` интерфейс предупреждает, что во время чтения коллекции
UniBridge может добавить сортировку и постраничную выборку. Размер страницы берётся из
`Query.Options.PageSize`; при отсутствии корректного значения интерфейс показывает обычное
для поддерживаемых версий значение `400`.

Отдельные блоки можно копировать. Стили и DOM-запросы ограничены контейнером `.xqi-root`,
чтобы не затрагивать коробочную разметку портала.

`Count SQL` показывается в обеих вкладках. Во вкладке выполнения он относится к созданному
UniBridge-запросу, но отдельно инспектором не выполняется.

Выполнение — не предпросмотр: оно действительно обращается к БД и читает коллекцию до конца.
Интерфейс не отображает и не сохраняет результирующие строки. Тайм-аут ограничивает текущую
SQL-команду и общий срок перечисления. Синхронную трансляцию внутри `provider.XQuery()` он
не может прервать, но после её завершения просроченный SQL уже не запускается.

Запросы и результаты не сохраняются в `localStorage`, не журналируются автоматически и не
отправляются на сторонние ресурсы. Копируемые данные могут быть чувствительными;
обезличивание при копировании не выполняется.
